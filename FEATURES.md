# Features

> Capability list for Scintilla. Stable IDs (`F-NNN`) are append-only.
> Acceptance criteria are observable, not design choices — design rationale lives in `DECISIONS.md`.

## Target users

Hobbyists and visual artists designing 3D LED animations — for the screen, for music-reactive installations, or as the design step before flashing a physical LED array. No graphics or audio-engineering background assumed.

## Out of scope

- Network or cloud sync; collaborative editing.
- Direct flashing to embedded hardware (deferred to a plugin — see `docs/SPEC.md` §6).
- Grid sizes above 32³ (DEC-005).
- 2D voxel grids (the product is fundamentally 3D).

## Editor & rendering

### F-001 3D voxel viewport with orbit/pan/zoom

**Priority:** Must
**Acceptance:**
- Mouse drag orbits the camera (azimuth + polar); wheel zooms; middle-drag (or shift-drag) pans the target point.
- Camera state is spherical (theta, phi, radius, target) — DEC-007.
- Default camera: theta = π/4, phi = π/3.1, radius = gridSize × 1.95.
**Status:** Prototype complete; production port in progress.

### F-002 Configurable grid size 3³–32³

**Priority:** Must
**Acceptance:**
- UI slider accepts integer values in [3, 32].
- Loading a JSON with `gridSize > 32` clamps to 32 with a warning (DEC-005).
- One-time UI warning shown the first time the user picks gridSize > 24.
**Status:** Not started (production).

### F-003 Shape masks: Cube, Sphere, Cylinder, Pyramid

**Priority:** Must
**Acceptance:**
- Each shape mask is generated by the algorithms in `docs/SPEC.md` §3.3.
- Switching shape with non-empty frames triggers a confirmation dialog (DEC-006).
- Ghost LEDs always render the full shape regardless of slice filter.
**Status:** Algorithms ported to `src/core/ShapeMask.h`; viewport integration pending.

### F-004 Paint tool

**Priority:** Must
**Acceptance:**
- Left-click on a visible LED sets it to the current colour.
- Slice-filtered LEDs cannot be painted (DEC-004).
**Status:** Prototype complete; production port pending.

### F-005 Erase tool

**Priority:** Must
**Acceptance:**
- Left-click on a lit LED removes it from the voxel dict.
- Respects slice filter.
**Status:** Prototype complete; production port pending.

### F-006 Fill tool

**Priority:** Must
**Acceptance:**
- Click floods all currently visible LEDs in the active slice with the current colour.
**Status:** Prototype complete; production port pending.

### F-007 Pick tool

**Priority:** Must
**Acceptance:**
- Click on a lit LED copies its RGB into the current colour (and into recent history).
**Status:** Prototype complete; production port pending.

### F-008 X/Y/Z slice view

**Priority:** Must
**Acceptance:**
- Three independent sliders (X, Y, Z); value `-1` means "show all"; value `N` shows only layer `N`.
- Slice filter applies to both rendering and tool application (DEC-004).
**Status:** Prototype complete; production port pending.

### F-009 Frame-based animation timeline

**Priority:** Must
**Acceptance:**
- Add, delete, duplicate, and click-to-select frames.
- Thumbnail strip rendered from frame contents.
- Minimum 1 frame; soft warning at 500+ frames.
**Status:** Prototype complete; production port pending.

### F-010 Animation playback

**Priority:** Must
**Acceptance:**
- Play / stop controls.
- FPS configurable per animation (default 12).
- Playback modes: play-once, loop, ping-pong.
**Status:** Prototype complete (play-once + loop); ping-pong is v1.0 production.

### F-011 RGB colour system

**Priority:** Must
**Acceptance:**
- Current colour exposed as [R, G, B] integers 0–255.
- 18-preset fixed palette + 16-slot LIFO recent history (deduplicated).
- Hex input field (v1.0 production addition).
**Status:** Prototype complete (sliders + palette + history); hex input pending.

### F-012 JSON save/load (v1.0 wire format)

**Priority:** Must
**Acceptance:**
- File round-trips losslessly: save then load reproduces the exact voxel state and timeline.
- Format matches the schema in `docs/SPEC.md` §3.8 / `docs/D-001-decisions.md` DEC-003.
- Off LEDs are absent from the voxels dict (sparse encoding).
**Status:** Wire format frozen; serialiser not yet implemented (`src/core/JsonSerializer.h` header only).

### F-013 Ghost LED overlay

**Priority:** Must
**Acceptance:**
- All addressable LED positions in the current shape mask render as low-opacity spheres (r=0.17, opacity=0.22, DEC-002).
- Toggleable via a checkbox.
**Status:** Prototype complete; production port pending.

### F-014 Auto-rotate viewport

**Priority:** Should
**Acceptance:**
- Toggle continuously increments camera theta.
- Rate configurable.
**Status:** Prototype complete; production port pending.

### F-015 Bounding box wireframe overlay

**Priority:** Should
**Acceptance:**
- Wireframe cube of side = gridSize rendered at opacity 0.11.
- Toggleable via a checkbox.
**Status:** Prototype complete; production port pending.

## Audio reactive

### F-016 Audio input device selection

**Priority:** Must (audio milestone)
**Acceptance:**
- UI lists PortAudio devices, including system monitor sources where available.
- User can switch device live without restarting the app.
**Status:** Header only (`src/audio/AudioDevicePicker.h` missing — see HANDOVER missing-files list).

### F-017 FFT-based spectral analysis

**Priority:** Must (audio milestone)
**Acceptance:**
- Hann-windowed FFT via KissFFT at ≥ 60 Hz update rate (`docs/D-002-audio-reactive.md`).
- Log-spaced band mapping (bass/mid/treble), onset detection on bass.
- PortAudio callback obeys the no-Qt / no-alloc / no-mutex rule (DEC-011, AV-008).
**Status:** Header only (`src/audio/FFTProcessor.h`).

### F-018 Reactive modes

**Priority:** Must (audio milestone)
**Acceptance:**
- Four modes available: EqBars, BeatPulse, WaveformSlice, SpectralColour.
- User-selectable at runtime.
**Status:** Header only (`src/audio/AudioReactiveEngine.h`).

### F-019 Mode blending

**Priority:** Should
**Acceptance:**
- Two modes can run simultaneously with a configurable blend weight.
**Status:** Not started.

### F-020 Capture audio-driven frames

**Priority:** Should
**Acceptance:**
- A "record" toggle appends each reactive frame to the animation timeline.
**Status:** Not started.

## Preset scripting

### F-021 Python preset subprocess engine

**Priority:** Must (scripting milestone)
**Acceptance:**
- Spawn Python subprocess; bidirectional JSON over stdin/stdout (`docs/D-003-preset-scripting.md`).
- Preset receives audio features each frame and emits a `VoxelFrame`.
**Status:** Header only (`src/scripting/PresetRunner.h`).

### F-022 In-app preset editor

**Priority:** Should
**Acceptance:**
- QPlainTextEdit with Python syntax highlighting.
- Preset browser list + error log panel.
**Status:** Header missing (`src/scripting/PresetEditorPanel.h`).

### F-023 Hot-reload on file save

**Priority:** Must (scripting milestone)
**Acceptance:**
- Editing a preset's `.py` file (in-app or externally) reloads it within one frame.
- Reload errors surface in the error log without killing the engine.
**Status:** Not started.

### F-024 Built-in preset library

**Priority:** Should
**Acceptance:**
- 20 reactive preset scripts in `presets/builtin/reactive/` plus shipped run-once animation scripts in `presets/builtin/animations/`, covering the demo set in `docs/D-003-preset-scripting.md` §DEC-021.
**Status:** 20 of 20 reactive presets complete; 2 animation scripts shipped (`anim_spiral`, `anim_lorenz`).

### F-025 User preset directory

**Priority:** Must (scripting milestone)
**Acceptance:**
- `presets/user/reactive/` and `presets/user/animations/` are the user-authored counterparts to the built-in directories.
- A template (`_template.py` for reactive, `_animation_template.py` for animations) is installed in each.
**Status:** Templates in place; File → New animation script… creates a fresh file from the animation template and loads it into the editor.

## Candidate features (uncommitted, v1.1+)

- **F-026** Stroke painting (click-drag draws a line of LEDs).
- **F-027** Undo / redo command stack (Ctrl+Z / Ctrl+Shift+Z).
- **F-028** Region selection with copy / paste / delete.
- **F-029** Mirror tools (X / Y / Z symmetry for paint).
- **F-030** HSV colour mode toggle.
- **F-031** Additional shapes: Torus, Ring.
- **F-032** Export to animated GIF (via ffmpeg or gif.js).
- **F-033** Export to MP4 (via ffmpeg).
- **F-034** Export to PNG sequence.
- **F-035** Export to C byte array (for flashing to original LED cube hardware).
- **F-036** Drag-to-reorder frames in timeline.
- **F-037** Per-frame duration override (vs. global FPS).
- **F-038** Custom user-editable palettes.
- **F-039** Custom imported mesh as shape mask.
- **F-040** Rotation keyframes for camera fly-through export.
- **F-041** Per-axis layer visibility toggles. Hide arbitrary layers along X, Y, or Z (multiple at once) so interior voxels become reachable by ray-pick. Extends F-008 single-slice view from "show one layer" to "hide any subset of layers." Motivation: ray-cast picking always lands on the outermost LED along the click ray; without a visibility filter, interior layers are unreachable. Surfaced during Phase 1 viewport testing on 2026-05-20.
- **F-042** Viewport orientation indicator. Small corner axis triad (X=red, Y=green, Z=blue, industry standard) rotating with the camera so the user can tell which face of the cube is currently top/front/etc. after free-orbiting. Implementation: secondary `glViewport` in the bottom-left, reusing `OrbitCamera`'s angles at fixed radius, ~80 lines plus a small `axis.vert/.frag` shader pair. Later upgrade path to clickable axis-snap (Blender-style, e.g. [three-viewport-gizmo](https://fennec-hub.github.io/three-viewport-gizmo/)). Skip Autodesk's ViewCube pattern (patent [US7782319B2](https://patents.google.com/patent/US7782319B2/en), in force until ~2027). Surfaced during Phase 2 testing on 2026-05-20.
